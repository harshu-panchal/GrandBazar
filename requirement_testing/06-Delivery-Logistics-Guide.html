Zinto Manual Testing Guide — Part 6: Delivery / Logistics Flow

Zinto Platform — Manual Requirement Testing Guide

This document walks a non-technical reviewer through testing how orders get delivered on Zinto — whether the platform's own delivery riders handle it, or the seller delivers it themselves. It covers the whole journey: a seller packing an order, an admin assigning a delivery rider, the rider picking up and delivering the order, and the settings that decide which delivery method is used for each seller. Use it by logging in with the admin, seller, and delivery-rider accounts you have been given, and following each numbered test in order.

How to use this guide

Each test below has a number and a short title. Follow the numbered steps exactly, in the app or portal named at the top of the test. After the steps, read the "✅ Expected Result" line and check that what you see on your screen matches it. If it matches, tick it off as passed. If it doesn't, make a note of what you saw instead so it can be reviewed. Some tests involve more than one person (for example, an admin doing one step and a rider doing the next) — a coloured tag on each test tells you which app/role to use.

18. Seller Logistics Flexibility / Logistics Participation Model

This section covers how a delivery gets from the seller's shop to the customer's door — either through Zinto's own delivery riders, or through the seller's own delivery staff — and how the admin manages that choice and assigns riders once an order is ready.

Seller packs order
→
Admin/platform assigns delivery rider
→
Rider picks up
→
Out for delivery
→
Delivered

(If the seller has chosen self-delivery instead, the middle "admin assigns rider" step is skipped, and the seller's own delivery staff carries out "picks up → out for delivery → delivered" using the Seller Panel instead of the rider app — see test 18.6.)

18.1 Seller's own choice: which delivery method to use

Seller Panel

Seller is not forced to use Zinto's delivery riders Ref: Req #184

  1. Log in to the Seller Panel with a seller account.
  2. Open the side menu and go to Delivery Policy & Availability (found under the shop settings area).
  3. Look at the "Fulfillment Methods" section at the top of the page.
  4. Notice there are separate on/off switches for Seller Self Delivery and Platform Logistics — they are independent tick-boxes, not a locked single choice.
  5. Turn off "Platform Logistics" and turn on "Seller Self Delivery" only, then tap Save delivery policy.
✅ Expected Result: The page saves without any error or warning that platform logistics is mandatory. A confirmation message "Delivery policy saved." appears, showing the seller is free to run deliveries themselves without being forced to use Zinto's delivery fleet.

18.2 The three delivery modes Zinto supports

Seller Panel

Platform-assigned delivery mode is available Ref: Req #185

  1. In the Seller Panel, go to Delivery Policy & Availability.
  2. Turn on the Platform Logistics switch and save.
  3. Place a small test order on the Customer App from this seller's shop (or ask someone to).
  4. Back in the Seller Panel, open Orders and find the new order.
  5. Confirm the order, then pack it: tap Mark as Packed when it becomes available.
✅ Expected Result: Once packed, the order's status shows "Updated by delivery partner" underneath it — meaning the order has been handed off to Zinto's delivery fleet and only a Zinto delivery rider (not the seller) can move it forward from here.
Seller Panel

Seller self-delivery mode is available Ref: Req #186

  1. In the Seller Panel, go to Delivery Policy & Availability and turn on only Seller Self Delivery (leave Platform Logistics off), then save.
  2. Place a test order against this shop.
  3. Open Orders in the Seller Panel and find the order.
  4. Use the status drop-down on the order row to move it through Confirmed → Packed → Out for Delivery → Delivered yourself.
✅ Expected Result: The seller can change the order's status all the way to "Delivered" directly from the Seller Panel, without ever waiting for a Zinto delivery rider to be assigned — proving self-managed delivery works end to end.
Seller Panel

A mixed / configurable delivery setup is supported Ref: Req #187

  1. In the Seller Panel, go to Delivery Policy & Availability.
  2. Turn ON both Seller Self Delivery and Platform Logistics at the same time, and also turn on Auto-switch to platform when seller unavailable.
  3. Save the settings.
  4. Place two separate test orders against this shop on different occasions (or ask the developer to confirm how the system chooses which method applies per order).
✅ Expected Result: Both options stay switched on together without the page blocking it or forcing an "either/or" choice — confirming the seller can offer a hybrid setup (their own delivery for some orders, Zinto's riders for others, with an automatic fallback to Zinto when the seller can't deliver).

18.3 Admin control over a seller's delivery mode

Admin Panel

Admin can set/override a seller's delivery mode Ref: Req #188

  1. Log in to the Admin Panel.
  2. Open Sellers from the side menu and open the profile of a specific seller (the seller's detail page).
  3. Look for a setting that lets the admin choose or override that seller's delivery method — platform logistics only, self-delivery only, or both.
  4. If found, change it and save; if not visible anywhere on the seller's profile or in Admin Settings, note that this control could not be located.
✅ Expected Result: The admin can view and change, from the Admin Panel itself, which delivery method(s) a given seller is allowed to use — without needing the seller to change it themselves from their own Delivery Policy page. (Today this control is set by the seller only; if the admin-side control is genuinely missing, this should be flagged back to the development team rather than marked as passed.)

18.4 Admin assigning a delivery rider after the order is packed

Order confirmed
→
Seller taps "Mark as Packed"
→
Order appears in admin's "Awaiting Rider Assignment" list
→
Admin picks a rider and confirms
→
Rider is notified
Seller Panel + Admin Panel

Admin can assign a delivery rider once the seller has packed the order Ref: Req #189

  1. As the seller: log in to the Seller Panel, open Orders, and for an order using platform delivery, tap Mark as Packed once it is ready.
  2. As the admin: log in to the Admin Panel and open Fleet Tracking from the side menu.
  3. Look at the panel titled "Orders Awaiting Rider Assignment" near the top of the page — the order you just packed should appear there, showing the seller's name, the customer's name, and how long it has been waiting.
  4. Tap the Assign button next to that order.
  5. In the pop-up, choose an available delivery partner from the list and confirm the assignment.
  6. Alternative route: instead of Fleet Tracking, you can also open the order directly from Orders in the Admin Panel, open its order detail page, and use the "Assign Fleet Rider" button in the Delivery Partner section there — it does the same thing for one order at a time.
✅ Expected Result: The order disappears from the "Awaiting Rider Assignment" list and a success message such as "Rider assigned successfully" appears. The order now shows the assigned delivery partner's name and status "Assigned" on both the admin order detail page and (when you check the rider app in test 18.5) on the rider's own dashboard.
Admin Panel

Admin can hand an order to an outside courier instead of an in-house rider Ref: Req #189 (related)

  1. Open an order's detail page in the Admin Panel (Orders → select an order that has been packed).
  2. In the Delivery Partner section, tap "+ Assign External Logistics (Dunzo / Porter / Delhivery)".
  3. Type the name of the outside delivery service being used and tap Save External Partner.
✅ Expected Result: The order's delivery status changes to show "EXTERNAL LOGISTICS" along with the courier name that was typed in, confirming the admin has flexibility to route an order outside Zinto's own rider fleet when needed.

18.5 Full delivery journey — end to end (rider app)

This walks through the platform-logistics journey from the rider's point of view once an order has been assigned to them, so the whole chain from packing to doorstep delivery can be confirmed in one pass.

Rider goes Online on Dashboard
→
Accepts assigned order
→
Navigate to Store → At Store → Picked Up Order
→
Start Delivery (Out for Delivery)
→
Confirm Delivery with OTP → Delivered
Delivery (Rider) App

Rider sees the assigned order and can go pick it up Ref: Req #189 (rider side)

  1. Log in to the Delivery App with the rider account that was just assigned the order in test 18.4.
  2. On the Dashboard, make sure the "Online/Offline" toggle at the top is set to Online.
  3. Open Order Details for the newly assigned order (it should also trigger a notification/alert).
  4. Tap through the delivery steps shown at the bottom of the screen in order: Navigate to Store → confirm "ARRIVED AT STORE" → confirm "PICKED UP ORDER" at the "At Store" step.
✅ Expected Result: Each step updates the order's progress bar on the rider's screen, and the order status visible to the seller and admin changes accordingly (e.g. to "Out for Delivery" once picked up). The seller's Delivery Tracking screen and the admin's Fleet Tracking screen both reflect the same rider and status.
Delivery (Rider) App

Rider marks the order "Out for Delivery" and completes delivery with OTP Ref: Req #189 (rider side)

  1. From the Order Details screen (after pickup), tap Start Delivery.
  2. Use the Navigation screen to travel to the customer's address.
  3. Once close to the customer (within the app's allowed distance), open Confirm Delivery and slide the on-screen button labelled "Generate Delivery OTP" to send a one-time code to the customer.
  4. Ask the customer for the code they received and enter it in the app to confirm.
✅ Expected Result: Once the correct OTP is entered, the order is marked Delivered in the rider app, and this same "Delivered" status is instantly visible to the customer, the seller, and the admin. The delivery earns the rider a completed-delivery entry on their Earnings screen.

18.6 Full delivery journey — end to end (seller self-delivery)

Seller confirms order
→
Seller marks Packed
→
Seller marks Out for Delivery
→
Seller marks Delivered
Seller Panel

Self-delivery orders can be fully managed by the seller, without a rider Ref: Req #190

  1. Confirm the seller's Delivery Policy & Availability has "Seller Self Delivery" turned on for this shop (see test 18.1).
  2. Place a test order against this shop.
  3. In the Seller Panel, open Orders, find the order, and change its status using the drop-down step by step: Confirmed → Packed → Out for Delivery → Delivered.
  4. Open Delivery Tracking in the Seller Panel side menu and check the order appears there while it is in progress.
✅ Expected Result: At no point does the order need a Zinto delivery rider to be assigned — the seller can move it all the way to "Delivered" themselves, and the order shows up correctly on the Delivery Tracking screen and to the customer as "Out for Delivery" and then "Delivered", exactly as if a rider had done it.
