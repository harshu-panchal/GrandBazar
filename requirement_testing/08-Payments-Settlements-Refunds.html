Part 8: Payments, Seller Settlements & Refunds

Zinto Platform — Manual Requirement Testing Guide
This document walks a non-technical reviewer through checking that refunds, complaints, seller payouts and settlement tracking all work correctly on the Zinto platform. Some tests are done as a customer in the app, some as an admin in the admin panel, and some as a seller in the seller portal — each test tells you clearly which one to use and where to log in. No technical knowledge is needed; just follow the numbered steps and compare what you see against the "Expected Result".

How to use this guide

Every check below is a numbered Test. Each test tells you which role/app to use, gives you simple numbered steps to follow (tap, click, type, etc.), and ends with an ✅ Expected Result — what you should see if everything is working. Go through the tests in order, tick each one off as you confirm the expected result matches what you actually see on screen.

How money moves through Zinto

Before testing the individual screens, it helps to see the two money journeys these tests cover: how a seller eventually gets paid for an order, and how a customer gets their money back for a return or complaint.

Order Delivered
→
Seller payout calculated (minus commission, GST, packaging charges)
→
Settlement Pending / On Hold (return window open)
→
Admin reviews, adjusts or releases
→
Settled to seller
Customer requests refund or raises a complaint (within allowed time window)
→
Admin reviews the request
→
Refund credited to Customer Wallet

29.1 Refund Access Window

This section checks that customers can only ask for a refund or complaint within a limited time after their order is delivered.

Test 1 — Refund/complaint option disappears after the allowed time Ref: Req #303

CUSTOMER APP
  1. Log in to the Zinto customer app and open My Orders.
  2. Open an order that was delivered less than 24 hours ago and scroll to the bottom of the order details screen.
  3. Confirm you can see a "Request Return" button and, further down, a box to raise a complaint ("Describe the issue" with a "Raise dispute" button).
  4. Now open (or wait for) an order that was delivered more than 24 hours ago and check the same screen.
✅ Expected Result: For the recently delivered order, the "Request Return" button and complaint box are visible and usable. For the order delivered over 24 hours ago, these options are gone — instead you should see a note such as "The complaint window for this order has closed", and no Request Return button.

29.2 Refund Countdown

This section checks that customers can see exactly how much time is left to raise a refund or complaint.

Test 2 — Countdown timer shown for refund/complaint window Ref: Req #304

CUSTOMER APP
  1. Open an order in My Orders that was delivered recently (within the allowed window).
  2. Scroll to the complaint section near the bottom of the order details screen.
  3. Look just above the "Describe the issue" box.
✅ Expected Result: A red line of text reading something like "Complaint window ends in 23:58:41" is shown, and the numbers count down live (in hours:minutes:seconds) each time you refresh or watch the screen for a few seconds.

29.3 Category-Based Refund Control

This section checks that the admin can decide which product categories are allowed to be refunded/returned at all (for example, perishable food or cosmetics may never be returnable).

Test 3 — Admin can turn refunds off for a specific category Ref: Req #305

ADMIN PANEL
  1. Log in to the Zinto admin panel and open Categories → Main Categories from the left menu.
  2. Click Edit on any category (for example, a category you would consider non-returnable, like a perishable food category).
  3. Find the checkbox labelled "Eligible for returns / refund".
  4. Untick this checkbox and save the category.
  5. Notice there is also a "Refund Window (hours)" field next to it — this lets the admin set a custom time limit for that category instead of the default.
✅ Expected Result: When the checkbox is unticked, the "Refund Window (hours)" field becomes greyed out/disabled, and saving succeeds. Products in that category should no longer show a Request Return option to customers. Re-ticking the box re-enables refunds for that category.

29.4 Wallet Refund for Cancelled Items

This section checks that money for items that get cancelled or are unavailable comes back into the customer's Zinto Wallet.

Test 4 — Cancelled/unavailable item amount is refunded to Wallet Ref: Req #306

CUSTOMER APP
  1. Place a test order that has more than one item.
  2. Have the seller mark one item as unavailable/cancel it (or cancel the whole order before it is packed) using the seller portal.
  3. In the customer app, go to Profile → Wallet (the wallet page shows the note "Return refunds are credited here").
  4. Check the wallet balance and the transaction list.
✅ Expected Result: A new credit entry appears in the Wallet for the value of the cancelled/unavailable item, and the wallet balance increases by that amount.

29.5 Refund Types to Support

This section checks the different kinds of refunds the platform must support: refunding the whole order, refunding only part of it, refunding a cancellation, and crediting the refund to the wallet.

Test 5 — Full refund for an order Ref: Req #307

CUSTOMER APP   ADMIN PANEL
  1. As a customer, open a delivered order in My Orders and tap "Request Return".
  2. In the "Request Return" pop-up, tick all items in the order, enter a reason, and submit.
  3. As admin, log in and open Orders → Return Requests, find this order and approve/process the return after quality check.
  4. Back in the customer app, check Profile → Wallet.
✅ Expected Result: The full order value is credited back to the customer's Wallet once the return is approved.

Test 6 — Partial refund for selected items only Ref: Req #308

CUSTOMER APP   ADMIN PANEL
  1. As a customer, open a delivered order with multiple items and tap "Request Return".
  2. In the pop-up, tick only one or two of the items (not all), enter a reason, and submit.
  3. As admin, approve this return from Orders → Return Requests.
  4. Check the customer's Wallet balance.
✅ Expected Result: Only the value of the selected items is refunded to the wallet — not the full order amount.

Test 7 — Refund for a cancelled order Ref: Req #309

CUSTOMER APP
  1. Place a test order and cancel it before it is packed by the seller (use the Cancel option on the order details screen, if the order is still in a cancellable stage).
  2. Check the payment method used (wallet balance, if used, or the record shown in Wallet/Transactions).
✅ Expected Result: Any amount already paid for the cancelled order is refunded back correctly (to Wallet, for wallet-based or prepaid orders).

Test 8 — Refund credited to wallet where applicable Ref: Req #310

CUSTOMER APP
  1. Repeat Test 5, 6 or 7 above (any approved refund).
  2. Open Profile → Wallet and check the transaction history entry for the refund.
✅ Expected Result: The refund transaction clearly appears in the Wallet history with the correct amount and date, and the usable wallet balance goes up by that amount.

29.6 Complaint Management

This section checks that raising a complaint about a delivered order follows the same time-window rule as refunds.

Test 9 — Complaint option follows the same window as returns/refunds Ref: Req #311

CUSTOMER APP
  1. Open a recently delivered order (within the allowed window) in My Orders.
  2. Scroll to the bottom — you should see the "Complaint window ends in [countdown]" text and a "Describe the issue" box with a "Raise dispute" button.
  3. Type a short description and tap Raise dispute.
  4. Now check an order delivered outside the allowed window and confirm the same complaint box is not available there.
✅ Expected Result: The complaint (dispute) option is only available while the countdown for that order is still running — the exact same cut-off used for returns/refunds. After submitting, you should see a confirmation and the complaint should show up for admin review.

30.2 Settlement Scope

This section checks that when the seller gets paid for an order, the amount properly accounts for the sale price and every deduction that should apply (commission, tax, packaging, refunds, cancellations, replacements, and platform charges).

Product selling price
−
Commission
−
GST / tax
−
Packaging & platform charges
−
Refund / cancellation adjustments
=
Final seller payout

Test 10 — Payout is based on the actual selling amount Ref: Req #313

SELLER PORTAL   ADMIN PANEL
  1. Note the price of a product before placing a test order for it.
  2. Place the order as a customer and have it delivered.
  3. As the seller, log in to the seller portal and open Earnings from the left menu.
  4. Find this order in the earnings list and check the amount shown for it.
✅ Expected Result: The payout amount shown for the order is based on the actual product selling price (quantity × price) charged to the customer, not an arbitrary or flat number.

Test 11 — Commission is deducted from the payout Ref: Req #314

ADMIN PANEL
  1. Open Sellers → Active Sellers in the admin panel and click into a seller.
  2. Go to the Order History tab and open the money breakdown for a delivered order (or use Orders → All Orders → [order] → View and check its money breakdown).
✅ Expected Result: The breakdown clearly shows a commission line item that has been subtracted from the seller's payout for that order.

Test 12 — GST/tax is accounted for in the breakdown Ref: Req #315

ADMIN PANEL
  1. Open the same order money breakdown as in Test 11.
  2. Look for a GST or tax line.
✅ Expected Result: If the product's category has GST configured, the breakdown shows the GST amount separately and it is factored into the final numbers correctly (not silently absorbed by the seller or the platform).

Test 13 — Packaging/handling charge sharing is reflected Ref: Req #316

ADMIN PANEL
  1. Place a test order for a product that has a packaging charge configured (check Products in the admin or seller panel for a packaging fee field).
  2. After delivery, open that order's money breakdown as admin.
✅ Expected Result: The packaging charge appears as its own line in the breakdown and is applied consistently with how the platform's packaging rules are configured (product-level charge if set, otherwise the category/default charge).

Test 14 — Refunds reduce the seller's settlement correctly Ref: Req #317

SELLER PORTAL
  1. Process a return/refund for a delivered order as described in Test 5 or 6.
  2. As the seller, open Earnings and find that order.
✅ Expected Result: The seller's payout for that order is reduced by the refunded amount (and its relevant share of commission/tax), instead of the seller keeping the full original payout.

Test 15 — Partial cancellations adjust the payout Ref: Req #318

SELLER PORTAL
  1. Have a seller cancel/mark unavailable just one item from a multi-item order before packing (as in Test 4).
  2. Once the order is delivered, check the seller's Earnings entry for this order.
✅ Expected Result: The payout only includes the items that were actually delivered — the cancelled item's value (and its share of charges) is excluded from the seller's earnings for that order.

Test 16 — Replacement orders affect payout correctly Ref: Req #319

CUSTOMER APP   SELLER PORTAL
  1. Trigger a replacement for an item (for example, respond to a seller-initiated price/item adjustment on an order that offers a replacement, visible on the Order Details screen as a "Replacement approval required" card).
  2. Approve the replacement as the customer.
  3. Once resolved, check the seller's Earnings entry for that order.
✅ Expected Result: The payout reflects the final replaced item(s), not the originally ordered item, and there is no double-charging or missing amount.

Test 17 — Platform charges/deductions are applied where relevant Ref: Req #320

ADMIN PANEL
  1. Open Fees & Charges in the admin panel and check what platform-level charges are configured.
  2. Open a recent order's money breakdown (via Orders → All Orders) and confirm any configured platform charge appears in it.
✅ Expected Result: Any platform charge configured under Fees & Charges shows up correctly in the order's money breakdown and is deducted from the seller payout as configured.

30.3 Settlement Status Tracking

This section checks that every order's payout to the seller shows a clear, up-to-date status.

Test 18 — "Pending" settlement status is shown Ref: Req #321

SELLER PORTAL
  1. Place and deliver a fresh test order.
  2. As the seller, open Earnings and find this order immediately after delivery.
✅ Expected Result: The order shows a status of "Pending" for its payout.

Test 19 — "Processing" settlement status is shown Ref: Req #322

ADMIN PANEL
  1. As admin, open Seller Payments from the left menu.
  2. Filter or look through the list for orders that are currently being processed for payout.
✅ Expected Result: Orders in the middle of being settled show a "Processing" status, distinct from "Pending" (not yet started) and "Settled" (fully complete).

Test 20 — "Settled" status is shown once payout completes Ref: Req #323

SELLER PORTAL
  1. Take an older delivered order whose return window (24 hours, or the category's configured window) has already passed and no complaint was raised.
  2. Check its status in Earnings.
✅ Expected Result: The order shows "Settled" once the return window has closed and the payout is released, with the amount now included in the seller's available/withdrawable balance.

Test 21 — "On Hold" status is shown Ref: Req #324

SELLER PORTAL   ADMIN PANEL
  1. As admin, go to Sellers → Active Sellers, open a seller, and in the Order History tab click "Hold" next to any order, enter a reason, and confirm.
  2. As the seller, check the Earnings page — look at the "On Hold (Return Window)" summary panel and the order's row.
✅ Expected Result: The order now shows an "On Hold" status to the seller, and its amount is excluded from the available balance until the admin releases it (or the automatic return-window hold clears).

Test 22 — Adjusted/deducted status after refund or cancellation Ref: Req #325

SELLER PORTAL
  1. Repeat Test 14 or 15 (a refund or partial cancellation on a delivered order).
  2. Check that order's entry in seller Earnings.
✅ Expected Result: The order clearly shows that its payout was adjusted/deducted due to the refund or cancellation, with the reduced amount visible, rather than showing the original full amount as still payable.

30.4 Settlement Rules

This section checks the underlying rules that decide when a seller's money actually gets released.

Order delivered
→
Return/refund window must fully pass
→
Commission & charges deducted
→
Held if a complaint/refund/cancellation dispute is open
→
Released to seller balance

Test 23 — Settlement only starts after delivery Ref: Req #326

SELLER PORTAL
  1. Check an order that is still "Being Prepared" or "On the Way" (not yet delivered) in seller Earnings.
  2. Confirm it does not yet show any payout amount as pending/settled.
✅ Expected Result: No settlement entry/status appears for the order until after it is marked Delivered.

Test 24 — Settlement waits for the return/refund window to close Ref: Req #327

SELLER PORTAL
  1. Check a freshly delivered order's status in seller Earnings — it should be "Pending"/"On Hold".
  2. Wait until the return window for that order has fully expired (or check an older order where it already has), then check the status again.
✅ Expected Result: The order only moves to "Settled" after its return/refund window has completely closed, never before.

Test 25 — Commission and charges are deducted before settling Ref: Req #328

SELLER PORTAL
  1. Open a Settled order in seller Earnings and view its amount breakdown.
✅ Expected Result: The amount that lands in the seller's available balance is already net of commission, GST, and other applicable charges — the seller never sees an inflated pre-deduction number credited to their balance.

Test 26 — Settlement is held during an open complaint/refund/cancellation dispute Ref: Req #329

CUSTOMER APP   SELLER PORTAL
  1. As a customer, raise a dispute/complaint on a recently delivered order (as in Test 9).
  2. As the seller, check that order's status in Earnings.
✅ Expected Result: The order's payout remains on hold/pending and is not settled while the dispute is unresolved.

30.6 Bulk Order Seller Settlement

This section checks that large/bulk orders (orders above a certain value or quantity) are settled with their own dedicated breakdown and rules, separate from regular orders.

Test 27 — Bulk orders get a separate settlement calculation Ref: Req #335

SELLER PORTAL
  1. Place a test order large enough to cross the platform's bulk/wholesale threshold (a high order value or a large quantity of one item).
  2. Have it delivered.
  3. As the seller, open Bulk Settlements from the left menu (below "Earnings").
✅ Expected Result: The bulk order appears as its own entry in the Bulk Settlements list, separate from the normal Earnings ledger, with its own seller-payout / commission / packaging / tax split.

Test 28 — Bulk order commission/margin rules are applied Ref: Req #336

SELLER PORTAL
  1. On the same bulk order from Test 27, open its row in Bulk Settlements to see the commission amount column/detail.
✅ Expected Result: The commission amount shown reflects the bulk-specific rule (for example, a different rate for orders over the threshold), not just the seller's normal commission rate.

Test 29 — Partial fulfilment/cancellation affects bulk order payout Ref: Req #337

SELLER PORTAL
  1. Have the seller fulfil only part of a bulk order (cancel or mark some line items unavailable) before delivery.
  2. After delivery, check the entry in Bulk Settlements.
✅ Expected Result: The payout only reflects the items actually fulfilled, adjusted the same way a partial cancellation would affect a regular order's settlement.

Test 30 — Settlement adjusts when a bulk order is delivered in stages Ref: Req #338

SELLER PORTAL
  1. If the bulk order supports multi-stage/partial delivery, have part of it delivered first and the remainder delivered later.
  2. Check the Bulk Settlements entry after each stage is delivered.
✅ Expected Result: The settlement amount updates correctly at each delivery stage and does not double-count or miss any part of the order once all stages are complete.

Test 31 — Admin can see the full bulk order settlement breakdown Ref: Req #339

ADMIN PANEL
  1. As admin, open Bulk Settlements from the left menu.
  2. Use the filters (status, order ID, date range) to find the bulk order tested above and click into its details.
✅ Expected Result: Admin can view the same seller-payout / commission / packaging / tax breakdown for the bulk order, along with running totals across all bulk orders at the top of the page.

30.7 Admin Settlement Controls

This section checks the tools admin has to review, adjust, hold, and manage seller settlements.

Test 32 — Admin can view seller settlement summaries Ref: Req #340

ADMIN PANEL
  1. Log in to the admin panel and open Seller Payments from the left menu.
✅ Expected Result: A summary view opens showing totals such as pending settlement amount and a list of sellers' transactions, filterable by status ("all", "paid", "pending").

Test 33 — Admin can view order-wise seller payable amount Ref: Req #341

ADMIN PANEL
  1. From Seller Payments, click on any individual transaction/order row to open its details.
✅ Expected Result: The details view shows exactly how much is payable to the seller for that specific order, along with its status.

Test 34 — Admin can apply settlement deductions/adjustments Ref: Req #342

ADMIN PANEL
  1. Open Sellers → Active Sellers, click into a seller, and go to the Order History tab.
  2. Find an order's payout row and click "Adjust".
  3. In the "Adjust Settlement" pop-up, choose whether to deduct or add an amount, enter the amount, type a reason, and click Apply Adjustment.
✅ Expected Result: A confirmation ("Settlement adjustment applied") appears, and the seller's payout for that order changes by the adjusted amount, with the reason recorded.

Test 35 — Admin can hold and release a settlement Ref: Req #343

ADMIN PANEL
  1. In the same Order History tab on a seller's detail page, click "Hold" next to an order's payout, enter a reason, and confirm ("Place on Hold").
  2. Confirm the order's row now shows "On Hold".
  3. Click "Release Hold" on the same order to release it.
✅ Expected Result: The hold is applied immediately (with a success message "Payout placed on hold") and stays held even after the normal return window would have expired, since it's a manual hold. Releasing it shows "Payout hold released" and the order becomes payable again.

Test 36 — Admin can manage bulk-order settlement cases Ref: Req #344

ADMIN PANEL
  1. Open Bulk Settlements from the admin left menu.
  2. Filter by status (PENDING / COMPLETED / CANCELLED), search by Order ID, or filter by date range.
  3. Open a bulk order's row to review its full breakdown, and cross-check it against the seller's own Sellers → Active Sellers → [seller] → Order History hold/adjust tools if a deduction or hold is needed.
✅ Expected Result: Admin can find, filter, and review any bulk order's settlement case from this dedicated page, and apply the same hold/adjust controls to it as a regular order when needed.
