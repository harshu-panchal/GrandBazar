Order Lifecycle, Scheduling & Cancellations

Zinto Platform — Manual Requirement Testing Guide
This document walks you through checking that every order — from the moment it is placed to the moment it is delivered, cancelled or refunded — is tracked correctly and shown clearly to everyone involved (the customer, the seller, and the admin team). It also covers scheduling a future delivery and every way an order can be cancelled or partly cancelled. Use this by logging into the Zinto customer app, seller app and admin panel with real test accounts and following each numbered test below.

How to use this guide

Each test below is numbered and belongs to a small reference tag (e.g. "Ref: Req #250") that matches our internal checklist. Follow the numbered steps exactly as written, using the real screens and buttons named in each step. Then compare what you see on your screen with the "✅ Expected Result" line — if it matches, you can tick that test off as working. If it does not match, note down the test number and what you saw instead, so it can be looked into.

24. Order Management – Complete Lifecycle

This section checks that a customer can always see exactly what stage their order is at, and that every stage of the journey — from placing the order to it being delivered or cancelled — shows up correctly on screen.

Order status is always clear and up to date Ref: Req #249

  1. Log in to the Zinto customer app.
  2. Tap the "My Orders" menu.
  3. Tap on any order in the list to open its order detail screen.
  4. Look at the progress tracker shown at the top of the screen.
✅ Expected Result: The tracker clearly highlights the exact stage the order is currently at (for example "Order Packed" or "Out for Delivery"), and the wording is plain and easy to understand.

The full journey a normal order goes through looks like this (some steps are skipped automatically for self-pickup orders):

Order Placed
→
Order Received
→
Order Accepted
→
Order Packed
→
Logistics Assigned
→
Out for Delivery
→
Delivered

"Order Placed" step shows right after checkout Ref: Req #250

  1. As a customer, add any product to your cart and complete checkout.
  2. Immediately go to "My Orders" and open this new order.
✅ Expected Result: The tracker shows "Order Placed" as the first completed step as soon as the order is submitted.

"Order Received" step shows the order has reached the seller Ref: Req #251

  1. Open the same order's detail screen a few moments after placing it.
✅ Expected Result: The tracker moves on to show "Order Received", confirming the order has reached the system/seller.

"Order Accepted" step shows once the seller accepts Ref: Req #252

  1. Log in to the seller app and open "Orders".
  2. Find the same order under the "Pending" tab and tap "Accept order".
  3. Go back to the customer app and re-open the order's detail screen.
✅ Expected Result: The tracker now shows "Order Accepted" as completed.

"Order Packed" step shows once the seller finishes packing Ref: Req #253

  1. In the seller app "Orders" screen, find the accepted order under the "Confirmed" tab.
  2. Tap "Mark as Packed".
  3. Go back to the customer app and check the order's tracker.
✅ Expected Result: The tracker shows "Order Packed" (or "Ready for Pickup" if this was a self-pickup order) as completed.

"Logistics Assigned" step shows once a rider is assigned Ref: Req #254

  1. Log in to the admin panel and open the delivery/logistics widget on the dashboard.
  2. Assign a rider to the packed order.
  3. Go back to the customer app and check the order's tracker.
✅ Expected Result: The tracker shows "Logistics Assigned" as completed. (For a self-pickup order, this step is not shown at all, which is correct.)

"Out for Delivery" step shows once the rider picks up the order Ref: Req #255

  1. Log in to the delivery app as the assigned rider.
  2. Mark the order as picked up / out for delivery.
  3. Go back to the customer app and check the order's tracker.
✅ Expected Result: The tracker shows "Out for Delivery" as completed. (This step does not appear for self-pickup orders.)

"Delivered" step shows once the order reaches the customer Ref: Req #256

  1. In the delivery app, mark the order as delivered.
  2. Go back to the customer app and check the order's tracker.
✅ Expected Result: The tracker shows "Delivered" (or "Picked Up" for a self-pickup order) as the final completed step.

"Cancelled" step shows clearly when an order is cancelled Ref: Req #257

  1. Place a new test order and cancel it right away (see the cancellation tests later in this guide).
  2. Open the cancelled order's detail screen.
✅ Expected Result: The tracker replaces the normal steps with "Order Cancelled", so there is no confusion about the order's state.

"Refund Initiated" message shows when money is returned Ref: Req #258

  1. Cancel or have an admin cancel a prepaid/wallet-paid order.
  2. Open that order's detail screen once the refund has been processed.
✅ Expected Result: The screen shows a message such as "Refund Initiated — the amount has been credited to your wallet." This only applies when money was actually collected upfront.

Every status change is visible to the customer Ref: Req #259

  1. Follow one order all the way from placing it to delivery, checking the order detail screen after each stage described above.
✅ Expected Result: Every single stage change appears on the tracker — none of the steps are silently skipped or left unclear.

Orders can be tracked in real time, without refreshing Ref: Req #260

  1. Keep the order detail screen open on your phone/browser.
  2. While it stays open, have the seller or rider move the order to the next stage from their app.
  3. Watch your screen without manually refreshing or reopening the page.
✅ Expected Result: The tracker updates on its own to the new stage within a few seconds, with no need to refresh.

25.1 Order Management - Admin Responsibilities

This section checks that the admin team has full visibility and control over every order placed on the platform.

Every order shows up in the admin panel Ref: Req #261

  1. Log in to the admin panel and open the "Orders" screen.
  2. Place a brand-new test order as a customer.
  3. Refresh the admin "Orders" list (leave it on "All Orders").
✅ Expected Result: The new order appears in the admin's order list, with its correct current status.

Admin can monitor and manage an order through its whole lifecycle Ref: Req #262

  1. In the admin "Orders" screen, switch between the different status tabs/filters (e.g. Pending, Scheduled, Confirmed, Packed, Delivered, Cancelled).
  2. Open a few different orders in each stage.
✅ Expected Result: Admin can see and open orders at any stage of their journey, from just placed through to delivered or cancelled.

Admin can update and manage orders Ref: Req #263

  1. Open any order's detail screen in the admin panel.
  2. Look for the available admin actions on this screen (for example approving/rejecting a cancellation request, or assigning a rider).
  3. Perform one such action.
✅ Expected Result: The action is accepted and the order updates accordingly, confirming admin has genuine control over the order, not just a read-only view.

Admin assigns logistics after the seller finishes packing Ref: Req #264

  1. Have a seller mark an order as "Mark as Packed" in the seller app.
  2. In the admin panel, open the delivery/logistics dashboard widget.
  3. Find that packed order (for orders using platform delivery, not self-pickup) and assign an available rider to it.
✅ Expected Result: The rider is successfully assigned, the order's stage becomes "Logistics Assigned", and the rider receives the delivery in their app.

26.1 Scheduled Orders

This section checks that customers can choose to have an order delivered on a future date instead of immediately.

Customer can schedule an order for a future date and time Ref: Req #273

  1. Add a product to your cart.
  2. Go to the cart/checkout screen and look for the delivery date and time picker.
  3. Choose a date and time slot in the future instead of "as soon as possible".
  4. Complete checkout.
✅ Expected Result: The order is placed successfully showing the chosen future date/time, and it appears under the "Scheduled" tab in the seller app's order list.

26.4 Advance Booking Window

This section checks how far in advance a customer is allowed to book a future delivery.

Check how far ahead a customer can book a future order Ref: Req #280

  1. Add a future-order (pre-order/scheduled) product to your cart.
  2. Open the delivery date picker on the cart/checkout screen.
  3. Scroll through the available dates to see the furthest date that can be selected.
✅ Expected Result: The app should let you book up to about a month ahead. Simply check what date range the app currently offers you — if the furthest available date looks much shorter than a month (for example, only about a week ahead), please flag this to the team so they can confirm the exact number of days that should be configured.

26.5 Cart Validation for Future Products

This section checks that the app recognises when a future-dated product is added to the cart.

Adding a future-order product is recognised by the cart Ref: Req #281

  1. Browse the catalogue and find a product marked for future/scheduled delivery.
  2. Add it to your cart.
  3. Open the cart screen.
✅ Expected Result: The cart recognises that a future-dated product is present and switches into its scheduling behaviour (see the next section). If nothing changes on the cart screen at all, please flag this to the team to confirm the intended behaviour.

26.6 Mixed Cart Scheduling Rule

This section checks what happens when a cart contains both a regular (immediate) product and a future-dated product together.

Mixing a regular product with a future-order product in the same cart Ref: Req #282

  1. Add a normal, immediately available product to your cart.
  2. Also add a future-order (scheduled) product to the same cart.
  3. Open the cart screen and check the delivery date/time shown for the whole order.
✅ Expected Result: The entire order should be treated as a scheduled delivery for the future date, rather than being split or delivered immediately. If instead the app blocks you from mixing the two, or splits them into separate deliveries, that is also worth noting — please confirm with the team which behaviour is intended.

All items in a mixed cart are delivered together on the scheduled date Ref: Req #283

  1. Using the same mixed cart from the previous test, complete checkout.
  2. Open the placed order's detail screen and check the delivery date shown for every item in the order.
✅ Expected Result: Every product in the order — both the regular one and the future-order one — shows the same future delivery date/window.

26.7 Cart Page as Scheduling Page

This section checks that the cart page turns into a date-scheduling screen whenever a future-order product is present.

Cart page shows a scheduling section for future-order products Ref: Req #284

  1. Add a future-order product to your cart.
  2. Open the cart screen.
✅ Expected Result: The cart page shows a delivery date/time picker section, letting you choose when this order should arrive, instead of the usual "deliver now" view.

Only valid, available future dates are shown Ref: Req #285

  1. With a future-order product still in your cart, open the date picker on the cart screen.
  2. Look through the dates that can be selected.
✅ Expected Result: Only dates on which this product can actually be delivered are shown as selectable — past dates or unavailable dates are not offered.

Only the seller's configured dates can be chosen Ref: Req #286

  1. Open the date picker on the cart screen for a future-order product.
  2. Try tapping on a date that was not specifically set up by the seller for this product (if any such date appears at all).
✅ Expected Result: You can only pick from the exact dates the seller configured for this product — any other date is either not shown or cannot be selected.

27.1 User Direct Cancellation Rule

This section checks that a customer can cancel an order themselves, instantly, as long as the seller has not yet accepted it.

Customer can instantly cancel before the seller accepts Ref: Req #287

  1. Place a new test order and do not let the seller accept it yet.
  2. In the customer app, open the order's detail screen.
  3. Open the "Order actions" panel and tap the cancel option.
✅ Expected Result: The order is cancelled immediately, with no need for anyone else's approval, and the tracker shows "Order Cancelled".

27.2 Post-Acceptance Cancellation Rule

This section checks that once a seller has accepted an order, the customer can no longer cancel it directly by themselves.

Direct cancel option disappears once the seller accepts Ref: Req #288

  1. Place a new test order.
  2. In the seller app, tap "Accept order" for it.
  3. Back in the customer app, open the order's detail screen and check the "Order actions" panel.
✅ Expected Result: There is no instant "cancel order" option any more — instead, only a request-based option is offered (covered in the next section).

27.3 Cancellation Request Flow

This section checks that once an order has been accepted (but a rider has not yet been assigned), the customer can only ask to cancel, and only an admin can approve it.
Customer opens "Order actions"
→
Raises cancellation request
→
Admin reviews in Order Detail screen
→
Admin taps Approve or Reject
→
Order cancelled (if approved)

Customer can raise a cancellation request after acceptance Ref: Req #289

  1. Using an order that the seller has already accepted (and packed, if needed) but for which no rider has been assigned yet, open the order's detail screen as the customer.
  2. Open the "Order actions" panel and choose the cancellation option.
  3. Enter a reason if asked, and submit.
✅ Expected Result: The customer sees confirmation that a cancellation request has been sent for admin review, rather than the order cancelling right away. (Note: once a rider has been assigned, or the order is already delivered/cancelled/disputed, no self-serve cancel option is shown at all.)

Only admin can approve and finalise the cancellation Ref: Req #290

  1. Log in to the admin panel and open that same order's detail screen.
  2. Look for the cancellation request details shown on the page (status "Pending Admin Action", who requested it, their reason, and when).
  3. Tap "Approve" to confirm the cancellation (or "Reject" to keep the order active).
✅ Expected Result: Only after the admin taps "Approve" does the order actually move to "Order Cancelled". Tapping "Reject" keeps the order running normally, and the customer cannot force the cancellation through themselves at any point in this flow.

28.2 Partial Cancellation

This section checks that when only some items in an order are unavailable, just those items can be cancelled while the rest of the order carries on.

Seller can cancel just the unavailable items, not the whole order Ref: Req #294

  1. In the seller app, open an order that has more than one item in it.
  2. Tap "Item Unavailable".
  3. In the item editor that opens, select the specific item(s) that are out of stock.
  4. Tap "Cancel {n} Item(s)" to confirm.
✅ Expected Result: Only the selected item(s) are removed/cancelled from the order. The remaining items stay on the order and continue through packing and delivery as normal.

28.3 Product Replacement Suggestion

This section checks that when a product is unavailable, the seller can suggest a replacement instead of simply cancelling it, and the customer decides whether to accept it.

Seller can suggest a replacement for an unavailable product Ref: Req #295

  1. In the seller app, open an order containing the unavailable product.
  2. Tap "Replacement" next to that item.
  3. In the "Request Replacement" screen, fill in the replacement product and a reason.
  4. Tap "SEND REQUEST".
✅ Expected Result: The replacement suggestion is sent successfully and appears on the customer's order for their decision.

Replacement is offered at the same price where possible Ref: Req #296

  1. While filling in the "Request Replacement" form as the seller, check the "Replacement price" field.
  2. Set it to match the original item's price (unless there is a genuine reason it must differ).
  3. Submit the request and check what price is shown to the customer.
✅ Expected Result: The customer sees the replacement offered at the same price as the original item, so they are not unexpectedly charged more.

Customer can accept or reject the replacement Ref: Req #297

  1. As the customer, open the order's detail screen after a replacement has been suggested.
  2. Open the "Order actions" panel where the replacement offer is shown.
  3. Try both outcomes on two separate test orders: accept the replacement on one, and reject it on the other.
✅ Expected Result: When accepted, the order updates to include the replacement product. When rejected, the original item is removed/refunded instead, and the order is not forced to include a product the customer did not want.

28.4 Partial Fulfillment / Split Availability Handling

This section checks the full set of options available when only part of an order can be fulfilled: cancelling and refunding what cannot be delivered, still delivering what can, keeping the customer informed, and offering a replacement.
Seller finds item(s) unavailable
→
Cancel unavailable item(s) + refund
→
Available items still packed & delivered
→
Customer sees updated order & refund

Unavailable items are cancelled and refunded Ref: Req #298

  1. In the seller app, mark one item in a multi-item order as unavailable using "Item Unavailable" and confirm the cancellation.
  2. As the customer, open the order's payment/summary details.
✅ Expected Result: The cancelled item's amount is refunded (shown as "Refund Initiated" and credited to the wallet, or the equivalent for the original payment method), and the order total updates to reflect only the remaining items.

Remaining available items are still delivered Ref: Req #299

  1. Using the same order from the previous test, continue the process for the remaining items: seller packs them, admin assigns a rider, rider delivers them.
  2. Check the order's tracker as the customer throughout.
✅ Expected Result: The remaining items continue normally through "Order Packed" → "Out for Delivery" → "Delivered", without being blocked by the cancelled item.

Customer is given an updated timeline for what could not be delivered Ref: Req #300

  1. After an item has been marked unavailable and cancelled, open the order detail screen as the customer.
  2. Look for any note about the removed item or an updated delivery estimate.
✅ Expected Result: The customer can clearly see that item was cancelled and is told what to expect next (for example, refund timing). If no such message currently appears anywhere on the order screen, please flag this to the team.

Replacement is offered as an alternative, with the customer's confirmation required Ref: Req #301

  1. Instead of cancelling the unavailable item outright, have the seller use the "Replacement" button and "Request Replacement" form to suggest an alternative product.
  2. As the customer, open the "Order actions" panel and respond to the replacement offer (accept or reject).
✅ Expected Result: The replacement is only added to the order after the customer actively confirms it — it is never swapped in automatically without their say-so.
